# Test fixtures

`media/` holds the smallest possible real files for each accepted type — a
32x16 JPEG, a three-frame GIF, a one-second MP4, and so on — plus hostile
ones: a decompression bomb, an SVG, an SVG named `.jpg`. They are made by
`scripts/make-media-fixtures.sh`, which documents what each one is for. They are committed
because the media pipeline's tests are worthless against synthetic bytes, and
tiny because they are read on every run. Anything large enough to matter is
generated by a pretest script instead, not committed.

`golden/` holds the expected `POST /api/1/upload` responses, one file per
scenario. They are compared **byte for byte on the serialised string**, not as
parsed JSON: field order and string-versus-number typing are part of
the legacy wire contract, and `assert_eq!` over two `serde_json::Value`s would
silently permit a regression in either. Use `insta::assert_snapshot!`, never
`assert_json_snapshot!`.

`golden/upstream/` is for responses captured from a real upstream instance,
diffed in an `#[ignore]`d conformance test. It is the only way to be certain
about the fields the upstream documentation gets wrong.
